# OCAP（失控行动预案）引导起草指南

> 用途：模式C 之外的独立能力——按"引导采集 + 出建议稿"方式帮工程师起草 OCAP。**绝不替用户凭空编写**：用户说实情，Agent 出结构化建议稿，用户拍板修订。

## 手册定位（新版 5.6 + 第9章图9-2）

- OCAP 是**事前制定的成文行动预案**，与控制计划的**反应计划部分相关联**（"tied to the reaction portion of the control plan"），并须随过程变化维护。
- OCAP ≠ 事后报告。第11章附录的报告示例（图 11-1/2/3）是**输出物模板**，不能替代 OCAP。
- 文件形态：手册不强制单独成册。推荐**锚点 + 配套件**三段式：
  1. 控制计划反应栏只写指向（"按 OCAP-xx Rev.x 执行"）；
  2. OCAP 本体一页流程图/一张表（职责 + 操作员调整矩阵 + 升级路径）；
  3. 记录件：过程日志表 + 培训确认记录。

## 四要素（缺一不合规）

| # | 要素 | 说明 |
|---|---|---|
| 1 | 职责界定 | 过程调整与升级措施由谁执行、谁批准 |
| 2 | 操作员调整矩阵 | 失控重复出现或规定循环内未恢复时，操作员按矩阵采取的分级动作 |
| 3 | 过程日志 | 记录每次调整、观察、措施（失控时填写） |
| 4 | 理解确认 | 操作员和主管理解并会用的证据（培训/考核记录） |

## 执行流程（图9-2 展开）

识别触发类型（单点出界/链/趋势…）→ 故障排除流程图查根因（5M）→ 产品处置 + 过程处置 + 文件化 → 判断是否升级（超出操作员权限 → 工程师 → 停线决策）。

## 引导采集流程（Agent 按此逐项问，每轮 1-3 问）

### 第一轮：工序背景
1. 这份 OCAP 针对哪个工序/哪张控制图？控制什么特性？
2. 该图目前选用了哪些判异准则？（若未选定，先引导回第9章选准则）

### 第二轮：失控场景与动作
3. 这个工序历史上出现过哪些失控类型？（点出界/连续偏移/趋势/周期）各自最可能的原因？
4. 每类失控，操作员**现在实际**会做什么？（调机参数？换刀？停线？叫谁？）
5. 操作员自己有权做哪些调整？调整几次不见效必须上报？上报给谁？

### 第三轮：处置与升级
6. 失控期间生产的产品怎么处置？（隔离/追溯范围怎么定？）
7. 什么情形必须停线？停线决策权在谁？
8. 调整和处置记录现在记在哪？（有无表单/系统？）

### 第四轮：落地保障
9. 操作员和班长接受过这套响应的培训吗？有记录吗？
10. 过程变更（换设备/换材料/改参数）时，谁负责同步更新 OCAP？

## 建议稿输出格式（采集完成后生成，写入用户工作目录，txt + md）

```
OCAP-<工序代号> 失控行动预案（建议稿 · 待用户确认）
1. 适用范围：工序 / 特性 / 控制图编号 / 判异准则清单（用户③②提供）
2. 职责界定表：动作 × 执行人 × 批准人（据⑤⑦生成）
3. 操作员调整矩阵：失控类型 × 第1次动作 × 重复出现动作 × 升级条件（据③④⑤生成）
4. 产品处置规则：隔离与追溯范围（据⑥生成）
5. 升级路径图：操作员 → 班长/工程师 → 停线决策（据⑤⑦生成）
6. 记录要求：过程日志表字段建议（据⑧生成）
7. 培训与维护：确认方式、更新触发条件（据⑨⑩生成）
附：控制计划反应栏建议措辞："按 OCAP-xx Rev.x 执行"
```

## 红线

- 用户未提供的实情**留空并标注【待补充：…】**，不得虚构填充。
- 建议稿标题必须带"建议稿 · 待用户确认"，判定权在用户。
- 不输出与用户工序无关的通用模板凑数。
